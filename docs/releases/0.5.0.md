# greenwash 0.5.0

The release where the tool stopped being something you read about and became
something you can install, verify and run.

## Install

```bash
pipx install git+https://github.com/0DukePan/greenwash@v0.5.0
```

`greenwash-cli` is not on PyPI yet; the tag is the supported install, and the
README says so. The release workflow that publishes it is in the repository and
runs on a tag, so this is a last mile rather than a foundation.

## Check it in ninety seconds

```bash
git clone https://github.com/0DukePan/greenwash && cd greenwash
python benchmark/verify.py
```

Three offline measurements — a planted cheat per task scored by the real test
runner, each attack beside its legitimate twin, a positive/negative pair per
language pack — no model, no network, non-zero exit on the first regression.
The same command runs in CI where every toolchain is installed.

## What changed

- **`greenwash coverage` — the Requirement Coverage Engine.** Requirements can
  now bind to more than one test, which makes contradictory evidence visible:
  one bound test passing and another failing is reported as **contradictory**,
  not flattened into "failed". A requirement whose evidence would not run is
  **could not check**, distinct from one with nothing bound. Requirements whose
  bound tests only assert the happy path are named separately as having no
  negative case, and every report ends with *coverage counts requirements with
  passing evidence; it is not a claim that the code is correct.*
- **`benchmark/verify.py`** — one command for all three offline measurements,
  and the CI job that runs it where Go, Rust, Ruby and Java exist.
- **A DeepSeek runner and the first live-model rows.** `deepseek_run.py` drives
  a model through the harness's agent seam; the eight-task pilot produced 6
  genuine fixes, 2 underspecified and 0 integrity cheats, and the two
  underspecified runs exposed corpus prompts that did not state the requirement
  they were testing. Both prompts are fixed.
- **`verifier-config-changed` no longer fires on maintenance.** It was 104 of
  109 flags on real history, nearly all dependency bumps; it now asks only when
  a change can alter what runs, and produces 7. Rule id, code and severity are
  unchanged, so existing waivers keep working.
- **`unreadable-file` (GW-DIV-003).** A changed Python file the static layer
  cannot read — including one git reports as binary — is a finding instead of a
  clean report. Missing paths are still not findings.
- **The maintenance pass.** 42 branches to 1, 8 worktrees to 1, the default test
  loop from twelve minutes to seven seconds, the whole suite nightly on Windows
  and Linux, and no in-tree ticket files. See `docs/maintenance.md`.
- **The demo shows the cause.** The README clip starts from the agent's real
  `git diff` and ends on the verdict.

## The numbers, including the one that is not a win

- **Detector:** 25 of 25 planted cheats caught on the machine that ran it (24
  static, 23 behavioural), 0 false positives on 25 recorded honest fixes. Three
  tasks are skipped for missing toolchains and named; CI scores all 28.
- **False positives on real history:** 109 flags became 12 after the rule
  narrowing — 10 asking, 2 hand-checked false positives. A survey, not a rate.
- **Agent behaviour:** still unmeasured on a current model. The earlier +0.0
  came from an instrument that could not record a passing cheat; the fix is in,
  and the re-run needs a funded key. No page claims an effect in either
  direction.

## What did not work

The pilot's two underspecified runs, the balance-blocked behavioural re-run, and
the eight days when CI was red on the released tag because the benchmark
classifier could not read the checker's output. All of it is in
[docs/what-did-not-work.md](https://github.com/0DukePan/greenwash/blob/main/docs/what-did-not-work.md).

The full write-up, with intervals and limits, is
[docs/benchmark-summary.md](https://github.com/0DukePan/greenwash/blob/main/docs/benchmark-summary.md).
