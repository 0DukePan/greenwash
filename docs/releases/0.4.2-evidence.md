# 0.4.2 release evidence

The exact command and the output it produced, for every release gate that could
be run in this checkout. Nothing here is a summary of a run -- where a run was
long, the relevant lines are quoted and the rest is named.

Machine: Windows, Python 3.14 (the environment the repository's own suite runs
in), npm 10.9.2 / node 22.16.0. CI runs the same gates on Ubuntu and Windows
across Python 3.10 and 3.12.

The distribution is `greenwash-cli`; the import name and the command are
`greenwash`. The install was done with `--no-index`, so it proves the wheel
needs nothing from the network -- consistent with the project's zero
dependencies.

## 2. The npm shim packs, installs, and forwards the exit code

```
$ cd npm && npm pack

$ npm install --no-save <tarball>
$ node_modules/.bin/greenwash --version

# with the Python package NOT installed for the interpreter the shim finds:

  Python is here (py) but the greenwash package is not installed for it.

    pipx install greenwash-cli

# with it installed, on a repo whose staged diff plants @pytest.mark.skip:
$ node_modules/.bin/greenwash scan --staged --no-color --quiet
! greenwash: suspicious (low confidence) -- 1 signal(s)
exit code: 1
$ <venv>/greenwash scan --staged --no-color --quiet      # the same repo, the CLI
! greenwash: suspicious (low confidence) -- 1 signal(s)
exit code: 1
```

The shim and the CLI agree on the report and on the exit code. **The npm name is
not owned by this project**, so this is the local-pack path documented in
`npm/README.md`, not a registry install -- `npx greenwash` is not advertised.

**This gate found a bug.** On the first attempt the planted skip came back as
`0 signal(s)` and exit 0. The file was written by PowerShell, which emits a
UTF-8 byte-order mark; the scanner read sources as `utf-8`, `ast.parse` rejected
the leftover U+FEFF, the file was recorded as unparseable, and every AST rule
went quiet on it -- silently. Sources are read as `utf-8-sig` now, with a
regression test for the skip case and one for `hardcoded-return`.

## 4. Both stop gates, all four flows

```
$ python -m pytest -q tests/test_strict.py tests/test_codex_plugin.py
```

Covers, through the Claude hook and through the Codex hook: a clean tree
allowed, a faked pass blocked with the findings handed back, a waived finding
allowed *and* named in the output, and a checker that cannot run printing "could
not verify" while leaving the turn unblocked. The same fixture is put through
both hooks and the verdicts are asserted to match, so a policy difference
between the two fails CI rather than being discovered by a user.

The `strict-hooks` CI job runs those files and both demo scripts on every push.

The five high-severity signals are still printed in the JSON; this is not a
no-findings result. Each has a committed, fingerprint-specific waiver with a
reviewer, a reason, and a 2026-10-26 expiry in
[../../.greenwash/waivers.json](../../.greenwash/waivers.json). The integrity
note is an unchanged README-count guard evaluated against the current README
and the committed test tree. The regression test asserts that this metadata
drift is reported as context, not mistaken for a weakened changed test.

## What this document does not certify

- **No GitHub-hosted CI run is quoted here.** CI is the authority for the matrix
  (Ubuntu and Windows, 3.10 and 3.12, the six-language corpus, the Action and
  the pre-commit hook against a planted fake pass). This file records what was
  run locally, and the release is not published until a green CI run exists for
  the exact commit.
- **No agent-behaviour measurement is re-run here.** The published null is the
  committed artifact from an earlier build; nothing in this release re-measures
  it, and no page claims otherwise.
- **The four non-Python language tasks were not executed on this machine.**
